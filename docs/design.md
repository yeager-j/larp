# LARP design (settled 2026-09-22)

Vocabulary is in [CONTEXT.md](../CONTEXT.md). Decisions with trade-offs are in [docs/adr](./adr). This file is the compact list of what was decided, for whoever builds it.

## Shape

- The `larp plan` process is the Relay. It holds the Run's Message queue, starts one Turn at a time, waits for the process to exit, reads its structured output, enqueues it, repeats. No daemon, no nesting, no polling.
- A Turn is a harness process. First Turn: `claude -p --session-id <uuid>` or `codex exec`. Later Turns: `claude -p --resume <uuid>` or `codex exec resume <thread-id>`. The Claude UUID is generated by larp; the Codex thread ID is read from the `thread.started` event.
- The Turn's structured final answer is the Message (ADR 0001). Claude: `--json-schema`, read from the `result` event's `structured_output`. Codex: `--output-schema <file> -o <file>`, read from the `-o` file, which holds only the last message.
- Exactly one active Turn per Run. A Participant may use its harness's own subagents inside a Turn.
- The Human can send a Message to any Role at any time from the TUI. Phase changes wait at a Gate for the Human.
- LARP touches no git and no repository files (ADR 0002).

## `larp plan` workflow

Roles: Planner, Reviewer, Implementer. Each is one model on one harness, chosen in the picker or by flags.

Phases:

1. **Planning.** Planner receives the task, replies `{to: reviewer, kind: request, body, plan}`. Relay writes `plan` to `~/.larp/runs/<run-id>/plan.md`. Reviewer reads the file, replies `{to: planner, kind: feedback | approve, body}`. Planner may reply `{to: human, kind: question, body}` only for product behavior, scope, external authority, or irreversible actions. Loop until `approve` or 3 rounds.
2. **Gate.** Shows the plan path and the last feedback. Human chooses: approve, send a Message to the Planner (stay in planning, reset the cap), or abort. Human may edit the plan file by hand first.
3. **Implementing.** Implementer receives the task and the plan path, replies `{to: planner, kind: question, body}` or `{to: human, kind: done, body}`. Planner answers questions or escalates to the Human. `done` ends the Run.

Schemas are per Role and enforced by the harness. No `plan_path` field; the Relay owns the plan file.

## Envelope

Every delivered Message is prefixed with: sender Role and model, Kind, absolute plan path once one exists, and a one-line reminder of the reply schema. The first Envelope to each Role also carries the original task text. The role prompt is prepended to the first Turn's prompt on both harnesses.

## Permission profiles

| Role | Claude | Codex |
|---|---|---|
| Planner, Reviewer | `--permission-mode plan --permission-prompts none --tools Read,Glob,Grep,ToolSearch,Skill,Agent,Write --allowedTools Read,Glob,Grep,ToolSearch,Skill,Agent --disallowedTools Bash,Edit,NotebookEdit,ExitPlanMode` | `-c sandbox_mode="read-only"` |
| Implementer | `--dangerously-skip-permissions` | `-c sandbox_mode="workspace-write"` |

Common to every Claude Turn: `--settings '{"disableAllHooks":true}' --effort <level> --model <model> --output-format stream-json --verbose --json-schema <schema>`. Common to every Codex Turn: `--json -m <model> -c model_reasoning_effort="<level>" -C <cwd> --output-schema <file> -o <file>`, stdin closed. Per-Role, per-harness extra args and the effort level come from `~/.config/larp/config.json`; defaults are effort `high`, no extras.

## Failure paths

- Output fails the schema: one retry with an Envelope saying so, then a Gate.
- Non-zero exit, `is_error`, auth or model-access errors: straight to a Gate showing stderr. No automatic retry.
- No Turn timeout in v1.

## Persistence

`~/.larp/runs/<run-id>/` holds `run.json` (task, Participants, session IDs, phase), `messages.jsonl` (append-only log, source of truth), `plan.md`, and per-Turn raw output. `larp resume <run-id>` continues from the log.

## CLI

- `larp plan [task]` with pickers, or `--planner <harness>:<model> --reviewer … --implementer …` for non-interactive use.
- `larp resume <run-id>`
- `larp runs`
- `larp show <run-id>`

## Rendering

Both event streams are mapped to one log: `Planner · claude-fable-5-1 · Read src/foo.ts`. `--quiet` prints only Messages and Gates. TUI pickers use `@clack/prompts`.

## Config

`~/.config/larp/config.json`: explicit model-to-harness list shown in the picker as `gpt-5.6-sol (codex)`, seeded from `~/.codex/models_cache.json` and a built-in Claude list; per-Role effort and extra args.

## Out of scope for v1

Generic user-defined workflows, parallel Turns, Turn timeouts, `codex queue` or live-session adapters, git branches or worktrees, a `larp send` command.
